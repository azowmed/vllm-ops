# experiments/ (AI-generated)

Everything in this folder was **generated by AI** (Claude Code) and run by the
repo owner: the code, the docs, the summaries and the charts. The raw data is
what the benchmarks actually measured. For the human interpretation, see
[`../findings/`](../findings/).

```
experiments/
├── src/                      code that runs and analyzes the experiments
│   ├── README.md             full runbook: start a GPU instance, run vLLM, sweep, analyze
│   ├── env.example           copy to <repo root>/.env (git-ignored)
│   ├── scripts/              00..06 shell steps (check, serve, wait, sweep, telemetry, ...)
│   ├── monitoring/           Prometheus + Grafana + dcgm-exporter, live and offline
│   └── analysis/             summarize.py (tables, cost, charts) + fixtures for tests
└── <gpu>/                    one folder per instance type: h100/, later l40s/
    ├── README.md             card specs, price, list of runs
    └── <date>_<label>/       one folder per run (one server config, one sweep)
        ├── README.md         config, data caveats, how to view
        ├── summary.md        generated tables + embedded charts  <- start here
        ├── summary.json      the same, machine-readable
        ├── charts/           PNGs from summarize.py
        ├── raw/              what the scripts wrote during the run (see below)
        └── prometheus-snapshot/  Prometheus TSDB, so the Grafana dashboards can be replayed offline
```

## Three ways to view a run

1. **Read it:** open `<run>/summary.md` (GitHub renders the tables and charts).
2. **Replay the Grafana dashboards** on your laptop, with no GPU needed (Docker required):
   ```bash
   cd experiments/src/monitoring
   ./seed_offline.sh ../../h100/2026-10-20_bf16-kv
   docker compose -f docker-compose.offline.yml up -d
   ```
   Then open the link in the run's README. Grafana's default "last 15 minutes"
   shows nothing, because the data is from the time of the run.
3. **Recompute it:**
   `python experiments/src/analysis/summarize.py --run-dir experiments/h100/2026-10-20_bf16-kv`
   (needs `pip install matplotlib` for the charts).

## What `raw/` contains

| File | Written by | Content |
|---|---|---|
| `vllm_c<N>.json` | `03_bench_sweep.sh` (`vllm bench serve`) | Per-level latency percentiles, throughput, errors |
| `startup.json`, `startup_lines.txt` | `02_wait_ready.sh` | Cold-start time, KV-cache tokens, max concurrency from the vLLM log |
| `env.json` | `05_collect_env.sh` | GPU, driver, CUDA, vLLM version, image digest, zone |
| `vllm_netlatency.json` | `03_bench_sweep.sh` | Client-to-server connect / TTFB probe |
| `metrics_c<N>_{before,after}.txt` | `04_snapshot_metrics.sh` | Raw vLLM `/metrics` around each level (preemptions, KV usage, ...) |
| `telemetry_c<N>.csv` | `06_gpu_telemetry.sh` | 1 Hz DCGM: SM / tensor / DRAM activity, power, clocks |
| `perf_c<N>_{before,after}.txt` | `06_gpu_telemetry.sh` | `nvidia-smi` perf / clock snapshot |
